## 多台电脑使用

1. 从当前本地工作区复制扩展文件到另一台电脑的稳定目录。运行必需文件：`manifest.json`、`background.js`、`lib.js`、`analytics.js`、`i18n.js`、`firebase-config.js`、`sync-core.js`、`stats-store.js`、`cloud-sync.js`、`offscreen.html`、`offscreen.js`、`dashboard.*`、`popup.*`、`icons/`、`_locales/`。不复制浏览器配置、登录令牌或扩展存储。
2. Chrome 116 或以上版本打开 `chrome://extensions/`，开启开发者模式，选择“加载已解压的扩展程序”。
3. 保留 manifest 的固定 `key`，各电脑的扩展 ID 应为 `idihkkiapagakajacljibnpekkfpiacm`。不要卸载当前扩展来完成普通更新。
4. 打开完整面板，在右上角设置 → 账户与同步中登录同一 Google 账户；在设备管理中修改各设备显示名称，设备 ID 保持不变。
5. 等待“已同步”，或点击“立即同步”。正常运行时约每 5 分钟同步一次；浏览器关闭期间不执行后台同步。

Firebase 同步数据，不分发扩展代码。每次更新需在对应电脑替换扩展文件，再点击“重新加载”。当前 GitHub 和商店版本不包含这次本地改动。

## 数据与冲突处理

- 原有本地 `dailyStats` 和 `reports` 保持为本机数据；首次登录直接上传这些历史记录。
- 每个浏览器配置使用独立随机设备 ID。云端按 UID、设备、日期分块存储；重复上传相同内容不重复累计。不同设备同时使用时分别计时，“所有设备”视图把这些时长相加，不进行时间重叠扣除。
- 概览可按显示名称选择设备或汇总所有设备，工具栏弹窗仍以本机统计为准。账户与同步分组显示头像、姓名、邮箱和同步状态；数据管理提供本机备份与恢复，设备管理支持跨设备改名。界面移除 Reports、Automatic Reports 和 Email Backup；后台清理旧报告闹钟，不再生成或发送报告。历史报告仅兼容保留、同步和 JSON 备份。
- 通用设置同步，最后成功上传的版本生效。设备名称独立设置，作为设备标签上传。旧报告/邮件配置不再参与通用设置同步；认证令牌和历史邮件凭据留在本地。
- 网络请求不进入计时的串行存储队列。离线继续写本地；错误显示在设置中，并在后续同步周期重试。
- 通过内容哈希与分块校验避免部分上传被读取；每个设备仅上传自己的原始记录，不把下载缓存再次上传为本机数据。
- “清除数据”保留原本的本机清除语义：只清除本机产生的记录，并在下一次成功同步后传播；其他设备的记录继续存在。删除本机报告同理。不要把“所有设备”视图当作全账户删除入口。
- 退出账户停止同步，缓存保留供离线查看。本机历史绑定首次成功同步的账户，避免换号后误上传到另一个账户；使用其他账户时应使用独立 Chrome 配置。
- 之前手动合并过的备份没有可恢复的设备来源。不要在多台电脑重复导入同一份合并备份，否则这些历史记录仍会按多份本机数据累计。
- JSON 完整备份继续导出本机原始数据、设置和历史报告；其他设备记录由 Firebase 保存。导入与导出入口保留在 Data 页面。
